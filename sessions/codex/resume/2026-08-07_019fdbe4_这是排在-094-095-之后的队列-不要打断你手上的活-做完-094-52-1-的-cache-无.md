用户是对的。绑定到 `0cd1abb6c1dddcb2d682b07fff879210fd351771`，我撤回“跨 T 是 artifact 格式性质”和“需要 900–1800 行重做映射”这两个判断。

1. T 在哪里进入映射

当前代码里有两种 T 依赖，必须分开：

- 合法的 T 依赖：MMA 的目标 fragment 本来就是 tactic 大小。

  [quactlize_mix_gemm_convert.h](/root/marlin_ppu/quactlize/quactlize/include/quactlize_extensions/cutlass/quactlize_mix_gemm_convert.h:217)：

  ```cpp
  value = (FoldF > 1) ? BlockK : (32 * 8 / Bits);
  ```

  这里 `BlockK=T`。它决定逻辑元素最终进入 T-sized fragment 的哪个寄存器，不决定 resident artifact 的物理格式。

- 错误的 T 依赖：copy/swizzle 的物理 quantum 也按 T 构造了。

  production 从 [quactlize_mma_builder.inl](/root/marlin_ppu/quactlize/quactlize/include/quactlize_extensions/cutlass/gemm/collective/builders/quactlize_mma_builder.inl:467) 开始：

  ```cpp
  blockK = TileShape.K;                   // T
  BFoldBlockK = ArtifactLowFold * blockK; // F*T
  DefaultOperandB<..., BFoldBlockK>
  ```

  offline 的同构位置是 [xplane_offline.hpp](/root/marlin_ppu/quactlize/quactlize/include/xplane_offline.hpp:48)：

  ```cpp
  BK       = F * TK;
  RowB     = BK * Bits / 8;
  AiuByte  = min(RowB, 128);
  AiuElem  = AiuByte * 8 / Bits;
  Op       = PPU0010_TSM_LD_SWZL<..., AiuElem, ..., InstNum>;
  LogicalTV = Copy_Traits<Op>::LogicalTV;
  ```

补 `dl` 只修复不同 delivery 写到同一 destination slot；残余耦合从这里开始：`LogicalTV` 本身仍由 `F*T` 构造。正确分解应该是：

```text
artifact delivery / copy map：由 A、F、bits 决定
tactic fragment destination：由 T 决定
dl：把前者的第 dl 个 delivery 接到后者相应的 fragment 区间
```

2. T 怎样进入 copy quantum

精确链路是：

```text
FullBlockK      = F * T
BlockContSize   = FullBlockK * bits / 8
AiuByte         = min(BlockContSize, 128)
AiuElem         = AiuByte * 8 / bits
InstNum         = FullBlockK / AiuElem
```

对应 [quactlize_mma_builder.inl](/root/marlin_ppu/quactlize/quactlize/include/quactlize_extensions/cutlass/gemm/collective/builders/quactlize_mma_builder.inl:96)；第二平面同样在该文件 [514](/root/marlin_ppu/quactlize/quactlize/include/quactlize_extensions/cutlass/gemm/collective/builders/quactlize_mma_builder.inl:514) 和 [528](/root/marlin_ppu/quactlize/quactlize/include/quactlize_extensions/cutlass/gemm/collective/builders/quactlize_mma_builder.inl:528)。

可直接手算：

```text
int2 A64 F2：artifact quantum = 2*64*2/8 = 32B
当前 T128：                   2*128*2/8 = 64B

int1 A64 F4：artifact quantum = 4*64*1/8 = 32B
当前 T128/T256：              64B / 128B
```

所以“quantum 随 T”不是硬件要求，是 builder 把“完整 tactic 物理跨度 `F*T`”和“单次 artifact copy quantum `F*A`”塞进同一个 `Block_K` 后产生的。

更直接的旁证是：[ppu_mixed_policy.hpp](/root/marlin_ppu/quactlize/quactlize/include/ppu_mixed_policy.hpp:153) 同时知道 T、A、F，但 [ArtifactFoldedSchedule](/root/marlin_ppu/quactlize/quactlize/include/ppu_mixed_policy.hpp:59) 只把两个 F 传给 builder，A 在这里丢了。F=1 时尤其无法从 F 反推出 A。

3. 规模修正

这不是改一行 `F*T → F*A`：完整 smem/gmem tile 的跨度仍必须是 `F*T`。需要把一个被混用的量拆成：

```text
FullBlockK = F*T   // 整块 tactic tile
CopyBlockK = F*A   // artifact copy/swizzle quantum
```

好消息是 builder 已经留了一个未接通的 `ContigShape_` 接口，[quactlize_mma_builder.inl](/root/marlin_ppu/quactlize/quactlize/include/quactlize_extensions/cutlass/gemm/collective/builders/quactlize_mma_builder.inl:60)，正适合做这个拆分。主循环的 `K_BLOCK_MAX/K_ATOM_PER_COPY` 又是从实际 retile 对象派生的，不需要先假设整条 mainloop 重写。
