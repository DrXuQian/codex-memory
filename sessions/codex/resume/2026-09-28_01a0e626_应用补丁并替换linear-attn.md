建议增加 **PPU1.7 + ACU 实机测试后端**，复用 H800 的逐 case 运行方式，以及 perfmodel 的模型汇总、对比和画图逻辑。

三种测试统一输出 `latency_us`：

| 测试方式 | 时间来源 |
|---|---|
| H800 | NCU/NSYS 的设备 kernel duration |
| PPU1.7 实机 | ACU 的设备 kernel duration |
| perfmodel | `compute_cycles / (GHz × 1000)`，单位 µs |

本地 SDK 的 ACU 耗时指标是 **`ppu__time_duration.sum`**。解析时必须读取单位，再转换为 µs；实测时间不需要再按 `--ghz` 换算。

建议增加这些接口，**目前尚未修改代码**：

1. **`bench_ppu17_hardware.sh`**：参考 `bench_h800_bandwidth.sh`，支持选择模型、prefill/decode 和单个 case，串行采集 ACU 报告。
2. **公共模型脚本增加 `--acu-latency`**：Qwen、MiniMax 都复用同一个 `run_case`，集中接入即可。关闭 perfrawlog 后处理，每个 case 保存 `.acurep` 和导出数据。
3. **`helpers/summarize_acu_kernels.py`**：排除初始化和 warmup，只汇总一次算子调用所需的 kernel；再复用现有调用次数计算模型 latency。
4. **比较脚本增加 `acu` 数据源**：保持现有横向双 bar、最大项在顶部的画法，支持 ACU 对 perfmodel、ACU 对 H800。

在 1.7 机器上，可以先用**已编译为 PPU1.7 的 GEMV 二进制**验证采集链路：

```bash

```

计时口径需要特别处理：

- ACU 的 replay、缓存策略要记录下来；不能直接把它与 warm-cache 多次平均时间混用。
- 模型总时间继续采用 `Σ(单次算子耗时 × 调用次数)`，缺失 case 显示为缺失。
- SOL 两个程序目前有 **10 次 warmup + 100 次运行**，应增加单次采集模式，否则直接求和会算错。
- 实机 GDN 使用 `LINEAR_GDN_MODE=device`，并加载匹配的 PPU1.7 扩展；当前默认安装路径是 CUDA SM90，单独改 mode 不够。
